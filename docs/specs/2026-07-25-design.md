# DukaSmart — Design Decisions (approved by Ian, 2026-07-25)

Companion to `2026-07-25-requirements.md`. The requirements fix the *what*; this fixes the
*how* where the spec left it open.

## D1. Location & build strategy
- Project: `~/Documents/Flutter/dukasmart`, git from the start (`main` branch).
- Build order (**Approach A**, approved):
  1. **Foundation (serial):** scaffold, theme, GoRouter shell + bottom nav, full Drift
     schema + DAOs + seed, shared widgets, KES formatter. Locks every interface.
  2. **Parallel feature tracks (Sonnet executors, worktree-isolated):**
     - Track 1: Product List, Add Product, Add Stock, Low Stock
     - Track 2: New Sale, Cart, Payment, Sale Success
     - Track 3: Expense List, Record Expense, Close Day, Daily Report, Home Dashboard
  3. **Integration (serial):** wiring, validation pass, review, acceptance test, APK.
- Folder structure exactly per requirements §"Project structure".

## D2. Money = integer cents
All monetary DB columns are `int` cents. Doubles drift under summation; this app's core job
is adding money. `intl` renders `KES 12,450` (no decimals shown when .00). `MoneyText` is the
only widget that renders amounts; input fields accept whole shillings and convert at the edge.

## D3. Data flow
- Drift schema exactly the six mandated tables. One DAO per feature area:
  ProductsDao, SalesDao, ExpensesDao, StockDao, DailyCloseDao.
- UI reads via Drift **watch queries** wrapped in Riverpod `StreamProvider`s → dashboard
  updates live, no manual refresh.
- **Sale completion is one DB transaction**: insert sale + items (with price snapshots) +
  decrement stock + insert movements. Stock-never-negative re-checked inside the
  transaction (UI check is advisory only). Add-stock likewise transactional.
- "Today" = local device date; daily queries filter `createdAt >= startOfToday`.
- Seed runs on first launch only (products table empty ⇒ seed).

## D4. Navigation & state
- GoRouter `StatefulShellRoute.indexedStack` for the 4 tabs (Home, Sell, Products,
  Expenses). Add Stock / Low Stock / Close Day / Daily Report are pushed routes from Home.
- Cart is a Riverpod `Notifier` held in memory only; abandoning it discards it (correct
  for a kiosk counter).

## D5. Dev loop while the Android SDK reinstalls
The machine's Android SDK is being reinstalled in the background (user-approved). Until it
lands, the app runs in **Chrome** via Drift's web support (sqlite3 WASM + drift worker
assets; `drift_flutter` auto-selects native SQLite on Android, WASM on web — same app code).
`mobile_scanner` / `image_picker` degrade gracefully where no camera exists.
Release APK is built at the end on the reinstalled SDK.

## D6. Validation, errors, empty states
- Form validators enforce all business rules (non-negative prices, cash ≥ total, M-PESA
  amount == total, expense > 0, etc.). DB transactions are the backstop.
- Every list gets an EmptyState; failed saves surface as snackbars.

## D7. Testing (deliberately minimal)
Unit tests only where arithmetic can silently lie: money formatting, close-day math
(gross profit, net result, expected cash, cash difference), sale stock-reduction
transaction. No widget-test suite — one-day scope.

## D8. Review & delivery
Each track gets an independent Sonnet xhigh review (routine CRUD tier). Then integration,
full acceptance-flow test in Chrome, `flutter build apk --release`, README with run/build
instructions.
